The finding

We formalised in Lean 4 the mathematics that turns DNA, RNA and protein sequences into Karnaugh maps: 131 machine-checked theorems, none left unproved. On this foundation every structure becomes an exact Boolean circuit whose rules hold without exception, for proteins, a viral species and folding simulations.

Gray-coded grids of sequences, from Petoukhov's genetic Karnaugh matrices1 to chaos-game maps (FCGR)2,3, are usually taken on trust. Here the encodings are theorems and every circuit and rule is checked on every case.

A code that changes one bit at a time

Binary counting can flip many bits at once: 0111 → 1000 flips four. The reflected Gray code g(n) = n ⊕ (n ≫ 1) visits every number once and changes exactly one bit per step. DNA needs two bits, and A C G T is itself a Gray cycle.

A Karnaugh map4 is a folded truth table

Order a grid's rows and columns by the Gray code and touching cells differ in one variable, even across the edges, which wrap like a torus. Put a k-mer's first letters on the rows and the rest on the columns: each 2-mer owns one cell of a 4×4 map, each 4-mer one of a 16×16 map.

Amino acids on a five-dimensional cube

Proteins need five bits: 32 codewords for 20 residues. Numbering residues group by group before Gray-coding keeps chemistry close. All 190 pairwise distances are proved: 40 pairs sit one bit apart, only four sit five apart, and the code uses exactly half of the cube's 80 edges.

Contacts as a Boolean function

A contact map is a Boolean function: C(i,j) = 1 when residues i and j lie within 8 Å. Quine–McCluskey5 merges 1-cells one bit apart into ever larger cubes; the cubes that cannot grow are the prime implicants, and a cover of them is a two-level circuit equal to the map. For an 8-residue example Lean proves the map symmetric and that no two of its contacts can merge.

⊢contactMap8_symmetric⊢contactMap_no_groupable_minterms⊢cc_cover_complete

How Lean checks a claim

In Lean 46 a statement is a type and a proof is a program checked by a small kernel. For finite claims, native_decide evaluates every case in compiled code, up to 220 in one theorem, and so also trusts Lean's compiler. No proof uses sorry or adds an axiom of its own.

-- Gray code is additive over GF(2)
theorem sc_gray_gf2_linear :
  ∀ x y : Fin 32,
    scGray (x.val ^^^ y.val)
      = scGray x.val ^^^ scGray y.val
  := by native_decide

What the proofs guarantee

Exact rules on padded maps

Twenty residues need five bits per axis, so a 20×20 residue-pair map is padded to 32×32 with 10-bit addresses. Lean proves that a fully fixed rule matches exactly its own cell and that any rule on real residues fires only inside the 20×20 block: padding never enters a result.

⊢cc_padding_safety⊢cc_fixed_match_unique⊢cc_off_avoiding

Segments hold under either numbering

With its low position bits free, a cube is an unbroken chain segment. Lean proves this for Gray-coded positions as well as plain binary: the two numberings name different segments, never broken ones.

⊢sc_gray_cube_is_also_interval⊢sc_gray_relabels_segments

What the encoding can and cannot change

Since g(x ⊕ y) = g(x) ⊕ g(y), a Gray-ordered map is a lexicographic (FCGR) map with its cells permuted: every statistic of the cell values is identical. The code changes only distances between letters: of the 400 ordered amino-acid pairs, exactly 80 are one bit apart.

⊢sc_gray_gf2_linear⊢cc_he_dist_counts◆120 / 120 maps: same cell values

Rules that hold in every frame of a folding run

In structure-based-model8 trajectories every native contact is formed or broken in every frame. Rules “whenever a is formed, so is t” that no frame breaks join neighbouring contacts; in ten long 8,000-frame runs, all of them do.

Rules with no exception, from exact circuits

Each PSICOV7 protein becomes a circuit equal to its contact map. Its AND gates are rules; block rules that continue one another give strand pairs, direction and register, by counting.

Takeaways

  • A verified foundation. Lean fixes the encodings and what every cube means; every circuit is exact on all inputs.
  • Rules that are true, not likely. Each holds for every contact, sequence or frame it names.
  • One language for sequence, structure and dynamics. Any finite encoding can be checked the same way.
